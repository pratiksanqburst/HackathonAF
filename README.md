## Problem Statement & Solution Overview


Decora is a full-stack single-page application built as a premium financial advisor workspace. It has three core pillars:

### 🗂 1. AI-Powered Deck Builder (the heart of the platform)

The **Deck Builder** is designed to remove the friction of creating professional client presentations from scratch. Here is the full workflow:

1. **Choose a template** — pick from 6 professionally designed presets (Quarterly Review, Portfolio Performance, Retirement Planning, Risk Assessment, Investment Recommendation, Two-Pot Advisory). Both the **Deck Library** and the **Templates page** render from the same shared data source (`presetTemplates.ts`) so they are always in sync.
2. **Configure the deck** — set the reporting period, meeting objective, focus areas, and toggle optional slide sections (benchmark comparison, charts, market outlook).
3. **AI drafts the content** — the platform calls a **Gemini 2.0** LLM (via the QBurst OpenAI-compatible gateway) to generate slide-by-slide bullet-point commentary tailored to the selected client's portfolio persona, risk metrics, and holdings. Each slide can be individually refined using the **AI Slide Refiner** with a custom instruction (e.g. *"make this more concise"* or *"add a risk caveat"*).
4. **Edit in the workspace** — a full drag-and-drop slide editor lets you reorder, delete, or add slides. The live slide preview scales to fit any screen.
5. **Export to PowerPoint** — one click generates a fully branded `.pptx` file using `pptxgenjs`. The deck includes the client's logo, brand colours, advisor footer, and all AI-generated commentary formatted into the correct slide layouts.

For even more flexibility, the **Custom AI Generator** (`/deck-config`) lets advisors describe any presentation topic in plain English and have Gemini construct a bespoke slide structure from scratch.

### 📊 2. Portfolio Analytics Dashboard

The dashboard surfaces live market data and client portfolio metrics. **All portfolio numbers (holdings, P&L, allocation %, Monte Carlo projections) are mock/simulated data** — they are generated by deterministic persona-based formulas and a 200-path Box-Muller Monte Carlo engine built into the Express server. Live market indices and news are fetched from **Yahoo Finance** with an auto-fallback to hardcoded values when the API is unavailable.

> ⚠️ **Mock Data Notice:** Portfolio values, Sharpe ratios, holdings, and returns shown on the dashboard are **illustrative demo data only**. They are not connected to any real brokerage, custodian, or live portfolio system. They exist to demonstrate the UI and AI commentary capabilities.

### 🤖 3. Gemini AI Engine

All AI features route through a **QBurst LLM Gateway** (OpenAI-compatible endpoint) using **Gemini 2.0 Flash** by default. The AI layer covers:

- **Slide commentary generation** — per-slide narrative bullets grounded in the client's persona, metrics, and holdings
- **Bulk deck drafting** — generates content for all slides in parallel
- **Conversational Copilot** — live chat with context awareness of the currently loaded portfolio
- **Stress Scenario Appraisal** — analyses how a selected macro shock (e.g. 2008 GFC, COVID crash) would impact the client's specific holdings
- **AI Theme Studio** — describe a colour/typography style in plain English and apply it across the entire deck
- **Custom Presentation Generator** — describe any topic and Gemini constructs a fully structured slide deck

If no API key is configured, **every AI feature gracefully falls back** to curated mock advisory responses — the app is fully usable in demo mode without any LLM credentials.

## Setup & Installation Instructions

Follow these steps to set up the repository and dependencies for either local development or containerized environments.

### Prerequisites
- **Node.js 18+** and **npm 9+**
- **Docker 24+** and **Docker Compose v2** (only if running via Docker)
- No database installation is required (uses embedded SQLite database file `deckora.db` generated automatically on start).

### 1. Clone the Repository
```bash
git clone <your-repo-url>
cd HackathonAF
```

### 2. Install Project Dependencies
Use the workspace installer script at the root directory to install client, server, and workspace root dependencies in a single step:
```bash
npm run install:all
```

### 3. Configure Environment Variables
Copy the server's example environment configuration and fill in the required variables (e.g. LLM API keys):
```bash
cp server/.env.example server/.env
```
Open `server/.env` and update the parameters:
```env
QBURST_GATEWAY_URL=https://llmgateway.qburst.build/v1
QBURST_API_KEY=<your-api-key>
GEMINI_MODEL=gpt-4o-mini
```
*Note: If `QBURST_API_KEY` is not provided, all AI capabilities (commentary drafts, custom slide builders, Copilot chat, and stress scenario appraisals) will automatically fallback to high-quality mock advisory responses.*

## Run Instructions

You can run Decora either directly on your host machine or containerized via Docker.

### Option A: Local Development Server (Recommended for Development)

Start the concurrent development runner from the project root:
```bash
npm run dev
```
This command runs both the frontend client and the backend API concurrently:
- **Frontend App**: [http://localhost:5175](http://localhost:5175) (Vite server with hot reload)
- **Backend API**: [http://localhost:5000](http://localhost:5000) (Express server)

*Note: Vite is configured to proxy all `/api` and `/uploads` requests to port 5000 automatically.*

### Option B: Docker Containerized Server (Recommended for Production/Verification)

Build and run the entire application containerized:
```bash
# Build the multi-stage image and start the service in background
docker compose up --build -d
```
The Docker setup does the following:
1. **Stage 1 (Build)**: Builds the production assets of the React frontend.
2. **Stage 2 (Runtime)**: Copies the built React assets into the Express server's public folder, installs production node modules, and starts the consolidated server.

The application will be accessible at:
- **Application URL**: [http://localhost:5000](http://localhost:5000)
- **Health Check Endpoint**: [http://localhost:5000/api/health](http://localhost:5000/api/health)

To stop and clean up the Docker containers:
```bash
# Stop containers
docker compose down

# Stop containers and remove volumes (WARNING: resets databases and uploads)
docker compose down -v
```


### Step-by-Step Instructions

#### Step 1 — Build the Docker image

```bash
docker build -t decora-insightsphere:latest .
```

This runs a two-stage build:
1. **Stage 1** — Installs client dependencies and runs `npm run build` (produces `client/dist/`)
2. **Stage 2** — Installs only production server dependencies and copies the built client into the server's `public/` directory

#### Step 2 — Configure environment

Create or edit `server/.env` with your LLM credentials:

```env
QBURST_GATEWAY_URL=https://llmgateway.qburst.build/v1
QBURST_API_KEY=<your-api-key>
GEMINI_MODEL=gpt-4o-mini
```

#### Step 3 — Start with Docker Compose

```bash
docker compose up -d
```

#### Step 4 — Verify the deployment

```bash
# Check container health
docker compose ps

# View logs
docker compose logs -f app

# Test the health endpoint
curl http://localhost:5000/api/health
# Expected: {"status":"ok"}
```

### Deploying to a Different Environment / Server

#### Option A — Via Docker Hub / Registry

```bash
# Tag and push to your registry
docker tag decora-insightsphere:latest your-registry.io/decora:latest
docker push your-registry.io/decora:latest

# On the target server:
docker pull your-registry.io/decora:latest
docker run -d \
  --name decora_app \
  -p 5000:5000 \
  -e NODE_ENV=production \
  -e QBURST_API_KEY=<your-key> \
  -e QBURST_GATEWAY_URL=https://llmgateway.qburst.build/v1 \
  -e GEMINI_MODEL=gpt-4o-mini \
  -v decora_uploads:/app/uploads \
  -v decora_db:/app \
  your-registry.io/decora:latest
```

#### Option B — Copy files to a Linux server and build there

```bash
# Rsync the project (excluding node_modules and DB)
rsync -avz --exclude='node_modules' --exclude='*.db*' \
  ./ user@your-server:/opt/decora/

# SSH into the server
ssh user@your-server
cd /opt/decora

# Create .env, then build and run
nano server/.env
docker compose up --build -d
```

#### Option C — Set a custom port

```bash
# Override port at runtime
PORT=8080 docker compose up -d

# Or set the port in docker-compose.yml:
ports:
  - "8080:8080"
environment:
  PORT: 8080
```

#### Option D — Behind Nginx reverse proxy

```nginx
server {
    listen 80;
    server_name your-domain.com;

    location / {
        proxy_pass http://localhost:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 120s;
    }
}
```

### Stopping and Cleanup

```bash
# Stop containers
docker compose down

# Stop and remove volumes (WARNING: deletes database and uploads)
docker compose down -v

# Remove the image
docker rmi decora-insightsphere:latest
```

## Troubleshooting

### `better-sqlite3` fails to build in Docker
The Dockerfile includes `python3 make g++` for native module compilation on Alpine Linux. If you see build errors, ensure you're using the provided Dockerfile without modification.

### AI features return mock data
This is expected when `QBURST_API_KEY` is not set or is invalid. Check the server logs:
```bash
docker compose logs app | grep -i gateway
```

### Port already in use
```bash
# Find what's using port 5000
lsof -i :5000
# Then either kill it or change the port:
PORT=8080 docker compose up -d
```

### Database reset
```bash
# Stop the container and remove the DB volume
docker compose down -v
docker compose up -d
```
